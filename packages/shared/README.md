# @todoapli/shared

**API のレスポンス型だけ**を置く（docs/06-infra-ci.md 6.1）。

| | |
|---|---|
| 置く | `TodoResponse` などレスポンスの形 |
| 置かない | バリデーションロジック |

サーバ側のバリデーション（不正な入力を拒む）とクライアント側のバリデーション
（ユーザーに親切なエラーを出す）は目的が違うので、二重に書くのが正しい（docs/02 の 2.3）。
共有すべきなのは「何が返ってくるか」だけ。

## ビルドしない

型しか入っていないので、コンパイル成果物を作らず **TypeScript のソースを直接参照**させている
（`exports` が `src/index.ts` を指している）。`import type` で読めば実行時の import は消える。

## api 側との重複について

`apps/api/src/todos/presentation/dto/todo-response.dto.ts` に同じ形の型がある。
API 側をここから import するように差し替えるかどうかは**あなたの判断**。

- 差し替える → 型が 1 か所になる。ただし presentation 層が外部パッケージに依存する
- そのまま → 二重定義になるが、API の内部表現とクライアント契約を独立に動かせる

どちらでも動く。決めたら理由を docs に 1 行残しておくと、案件で聞かれたときに答えられる。
